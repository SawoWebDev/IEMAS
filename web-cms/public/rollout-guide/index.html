Before you start

How it fits together

One server PC runs IEMAS in Docker. It reads the company mailboxes, decides which emails are customer inquiries, and tracks every inquiry until the employee confirms it is resolved. Each employee's PC runs the small IEMAS Agent app, which receives the pop-ups. Managers only get an email when an inquiry is escalated.

Nothing to install in Outlook. Employees keep replying from Outlook as they do today. IEMAS sees the reply in the mailbox's Sent folder within about 2 minutes and stops the reminders by itself.
Part 1 · once

Set up the server PC

Who: IT administrator. Use an always-on Windows PC or server with at least 8 GB RAM and a fixed IP address on the office network (in this guide, 172.16.2.68).

  1. Install Docker Desktop

    Download Docker Desktop for Windows from docker.com, install it with the default WSL 2 option, restart, and start Docker Desktop once. In Docker Desktop's Settings → General, tick Start Docker Desktop when you sign in so IEMAS comes back after a reboot.

  2. Get the IEMAS files

    Install Git for Windows, then in a command prompt:

    cd C:\
git clone https://github.com/SawoWebDev/IEMAS.git IEMAS
cd IEMAS

    Before every update, back up the database with scripts/backup-database.sh (run it from Git Bash). Then run git pull and double-click Build-IEMAS.bat again. Database changes are applied when the API starts.

  3. Fill in the settings file

    Copy .env.example to .env in the same folder and open it in Notepad. Fill in these lines:

    SettingWhat to put
    POSTGRES_PASSWORDA long random password for the database.
    JWT_SECRETRandom, at least 32 characters. IEMAS refuses to start with a short one.
    AGENT_JWT_SECRETAnother random value, different from JWT_SECRET.
    CREDENTIAL_ENCRYPTION_KEYRandom 32 bytes in base64. Encrypts the stored mailbox passwords. Keep a copy safe: losing it means re-entering every mailbox password.
    BOOTSTRAP_ADMIN_EMAIL / _PASSWORDYour own CMS login. Created on the first start only.
    OPENROUTER_API_KEYThe AI key from openrouter.ai/keys.
    DOMAINThe server's IP address, for example 172.16.2.68 (or a DNS name if you have one).
    CORS_ORIGINhttps://172.16.2.68:8443 (the address people open the CMS on).
    ASPNETCORE_ENVIRONMENTLeave as Production.

    To make the random values, run this in PowerShell once per secret and paste the result:

    [Convert]::ToBase64String((1..48 | % { Get-Random -Max 256 }) -as [byte[]])

    For CREDENTIAL_ENCRYPTION_KEY use 1..32 instead of 1..48.

  4. Double-click Build-IEMAS.bat

    It builds and starts the database, the API, the CMS website and the HTTPS proxy, then checks each one. The first build takes 5–10 minutes. It ends with Done. and lists anything that failed. A full log is written to the logs folder.

    The proxy listens on ports 8080 and 8443. On a dedicated server you can use 80/443 instead by adding PROXY_HTTP_PORT=80 and PROXY_HTTPS_PORT=443 to .env.

  5. Open the firewall

    Employee PCs must reach the server on port 8443. In PowerShell as administrator:

    New-NetFirewallRule -DisplayName "IEMAS HTTPS" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow

  6. Log in to the CMS

    From any PC open https://172.16.2.68:8443. The browser warns about the certificate the first time because the server made its own; choose Advanced → Continue. Log in with the admin email and password from .env.

  7. Schedule a daily backup

    Add a daily Windows Task Scheduler job that runs scripts\backup-database.sh from Git Bash. Backups land in the backups folder; copy them off the server.

Part 2 · once

Configure IEMAS in the CMS

Who: IT administrator, with the list of mailboxes, employees and managers. System → Setup Checklist shows what is still missing; work down it until every line is green.

Every missing setting is listed with a Fix link. Work down the list until nothing is marked as missing.

  1. Add the employees

    People & Devices → Employees. Add the employees and managers, and set each person's Supervisor. When an employee signs in on their PC (Part 3), their record is created if it is missing.

  2. Add each mailbox and choose its owner

    Email → Email Accounts → Add. For a company address, enter only the email address and password. The mail server, ports, encryption and domain come from Mailbox defaults in System Settings (mail.sawo.com, IMAP 993, SMTP 465, SSL/TLS, sawo.com), so they are already filled in. Press Test connection, then Add account. The owner (the employee whose PC gets the alerts) is chosen automatically by email address. Set the owner's Supervisor on the Employees page, or escalations for this mailbox have no recipient.

    Employees can also sign in with their own mailbox from their PC (Part 3), so you do not have to collect passwords. To stop that, switch off employee self-registration in the Mailbox defaults group.

  3. Set the outgoing mail account

    Email → Outbound Email. One SMTP account IEMAS uses to send escalation emails, practice samples and the confirmation email sent when a PC connects. Test connection checks the login without sending anything. Once the employees are set up, use Test escalation on an employee's row (Employees page) to send a real sample to their manager.

  4. Set who gets escalations

    Managers are added as employees too. On Employees, set each person's Supervisor: escalation emails go to the supervisor. To reach a whole team instead (for example "Sales managers"), create it under Alerts & Escalation → Escalation Groups and name it in Escalation Policies.

  5. Set working hours and holidays

    Alerts & Escalation → Reminder Policies → Default. The office hours are pre-set to Monday to Thursday 07:00-18:00 and Friday 07:00-16:00, Asia/Manila time. Add the public holidays. Every deadline counts only these hours, and reminders and escalations are only sent during them. Friday is set to 16:00 on purpose: on days people stay until 18:00 they still get pop-ups and their replies count, but nobody is escalated for leaving on time.

    Add the holidays before go-live, otherwise a holiday counts as a normal working day.

  6. Check the timings

    The defaults are: first reply 8 working hours; 2 reminders 4 working hours apart; supervisor emailed 4 working hours after the last reminder; customer follow-up 1 business day; quiet conversation 3 business days; customer silent 5 calendar days; waiting on a colleague 2 business days; resolution target 10 business days; next escalation level 2 business days later.

    Settings changed before this version keep their old values. In System → System Settings, reset any timing you had changed to these defaults, or keep it on purpose.

  7. Check the system is healthy

    System → System Health. All background jobs should show a recent successful run. In System → System Settings, set CMS web address to https://172.16.2.68:8443 (the "Open case" button in escalation emails uses it), and make sure TEST MODE: count hours as minutes is off.

Part 3 · on every employee PC

Install the IEMAS Agent

Who: an administrator downloads the installer once; the employee runs it and, if asked, signs in with their work email and password. About 2 minutes per PC.

  1. Download the installer from the CMS

    People & Devices → Windows Agents → Download installer. Choose who it is for:

    • One person (pick their mailbox): nothing to type on the PC at all. Best when IT sets up each PC.
    • Everyone: one zip for the whole team; each person types their own work email and password once.

    Check the server address (the address the PCs use, for example https://172.16.2.68:8443), then Download zip. An https address also tells the Agent to accept the server's own certificate, so there is no certificate option to set.

    Installers do not expire and have no PC limit. The Installers downloaded list under the button shows each zip and lets you Withdraw it: PCs already connected keep working, but the withdrawn zip cannot connect new PCs.

    Treat the zip like a password. Until you withdraw it, anyone who runs it can connect a PC to IEMAS for the mailbox it allows. Send it directly to the person, not to a group or a shared folder.

  2. Run it on the PC

    Copy the zip to the PC, right-click it and choose Extract All…, then double-click Install-IEMAS-Agent.bat in the extracted folder. If Windows asks whether to run it, choose Run (or More info → Run anyway).

    The installer does the rest by itself:

    • installs the .NET 8 Desktop Runtime if the PC doesn't have it (Windows may ask to allow the change: click Yes),
    • installs the Agent for the signed-in user and adds it to the Start menu,
    • sets the server address and certificate option, and turns on Start with Windows,
    • starts the Agent. A one-person installer connects straight away and is approved automatically. An Everyone installer asks for the work email and password (next step).

  3. Check the light is green

    With a one-person installer, the Agent shows ● Connected and the employee's name within a few seconds. Otherwise the person types their work email and password, clicks Test connection, then Connect. IEMAS checks the password with the company mail server, adds the mailbox to the CMS, approves the PC and sends a confirmation email to their inbox.

    If the mailbox owner already has other mailboxes under a different email address, the PC waits for an administrator to approve it under Windows Agents. On a PC that came from an installer, the sign-in screen offers Connect with the installer instead (email only); on other PCs it offers Ask an administrator to approve this PC instead.

    Use the https address (port 8443). The password travels from the PC to the server; the Agent asks before sending it over plain http. Five wrong passwords for one address stop sign-in for 15 minutes.
Setting up a PC by hand instead (no installer)

With employee self-registration on (the Mailbox defaults group in System Settings), a PC set up by hand needs only the server address and the work email and password. The approval steps below are for when it is off.

Install the runtime with winget install Microsoft.DotNet.DesktopRuntime.8, copy IemasAgent.exe from the server's windows-client/agent-release folder and start it. In Settings enter the server address and Save. Tick Allow self-signed certificates only if your administrator tells you to. Register with the company email address; the PC then appears as Pending under Windows Agents until an administrator chooses the employee and presses Approve. A withdrawn installer falls back to this same Pending request.

Updating the Agent later: download a new installer and run it the same way. The registration is kept.
Part 4 · for every employee

Using the Agent the first time

The first time it connects, the Agent opens Show me around: five short pages. They explain what appears on the PC and the reply and escalation times for that employee, and end with a practice inquiry that goes from new email to escalation while they watch. Only that employee receives its pop-ups and emails. The practice inquiry is removed when they press Finish, or after 1 hour. It can be opened again from the Help tab or the tray icon's menu, and an administrator can start a practice run for a PC from Windows Agents → Practice run.

The Agent shows the inquiries that need you. You still answer customers in Outlook. When the customer's request is fully handled, you confirm it in the Agent.

ButtonWhen to use it
✉ Reply in emailOpens Outlook. Reply to the customer's email from the same mailbox. IEMAS finds your reply by itself within about 2 minutes.
✓ Mark as resolvedThe customer's request is fully handled. A first reply alone does not close an inquiry.
Yes, it's resolved / Not resolved yetShown when IEMAS thinks the conversation is finished. IEMAS never closes an inquiry by itself; you decide.
I'm working on itShows you picked it up. Reminders continue until your reply is found.
Waiting on a colleagueYou need information from someone inside the company first. It moves to the Waiting tab and you get more time.
Remind me in 1 hourPops it up again in an hour. Deadlines still apply.
Not a customer inquiryFor emails flagged by mistake (spam, newsletters, personal mail). Closes it.

Closing the window does not stop the app. It hides to the tray icon next to the clock, and pop-ups keep coming. Only right-click → Exit stops it.

If something is not right

Troubleshooting

The Agent stays on "Connecting…"

Check the Server URL in Settings (https, port 8443). Tick "Allow self-signed certificates" only if your administrator tells you to; the installer sets it for you. From the PC, open https://172.16.2.68:8443 in a browser: if that fails too, check the server's firewall rule and that Docker Desktop is running on the server.

Sign-in fails, or the PC says it is waiting

The email must be a mailbox IEMAS watches, with an owner set on the Email Accounts page. A PC waits as Pending under Windows Agents when the mailbox owner has other mailboxes under a different email address, or when it was set up by hand: approve it there. A withdrawn installer still installs the Agent, and its PC waits in the same way.

Sign-in says the password is wrong or there were too many attempts

Use the password you use in Outlook for that mailbox. After 5 wrong passwords for one address, sign-in waits 15 minutes before it accepts another try.

I replied but still get reminders

Wait 2 minutes for the Sent-folder check. Reply to the customer's own email (not a new email) from the mailbox the customer wrote to. If you answered by phone, open the inquiry and use Mark as resolved or add a note.

A customer email did not become an inquiry

Allow a couple of minutes. Newsletters, auto-replies and internal mail are filtered out on purpose. An email the filter calls an inquiry is double-checked by the AI; if the AI cannot be reached, the filter's decision stands. Emails the AI was unsure about wait for a supervisor in the Review queue (Email → Email Classification).

No pop-ups appear

The tray icon's dot must be green. Pop-ups go to the owner of the mailbox the email arrived in. Pop-ups missed while the PC was off are shown when it connects again.

Nothing works after the server restarted

Docker Desktop must be running. Double-click Build-IEMAS.bat again; it starts everything and reports what is wrong.
